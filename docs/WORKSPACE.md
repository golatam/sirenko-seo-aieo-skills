# Переносимые пути и хранение

Пакет не привязан к домашнему каталогу автора, системе заметок или конкретному runtime. Переменные ниже — согласованная с оператором **конвенция workspace**, а не скрытый autoconfig. Утилиты принимают явные пути через CLI; сами не загружают `.env`, credential files или пользовательские проекты.

| Переменная | Назначение |
|---|---|
| `SEO_PACK_ROOT` | Абсолютный путь к этому checkout |
| `SEO_SKILLS_ROOT` | По умолчанию `${SEO_PACK_ROOT}/skills`; после разрешённой установки — выбранный host skill root |
| `SEO_ARTIFACTS_DIR` | Приватный каталог вне checkout для HTML, ответов, exports, evidence и test reports |
| `PROJECT_DOCS_DIR` | Приватные читаемые проектные решения/brief/журнал; может быть Vault, но он не обязателен |
| `SEO_TRACKER_DIR` | Необязательный путь к **внешнему**, уже одобренному и проверенному tracker. Если его нет, не создавать автоматически |
| `TMPDIR` | Существующий абсолютный разрешённый scratch-каталог вне checkout для тестовых временных файлов |

Первые два пути задаются явно, абсолютным путём к вашему checkout:

```bash
export SEO_PACK_ROOT="/absolute/path/to/this/checkout"
export SEO_SKILLS_ROOT="$SEO_PACK_ROOT/skills"
```

Остальные пути задаёт оператор по своей среде и правилам доступа; примеры `<project>`, `<run-id>` и `<date>` в инструкциях — placeholders, не реальные каталоги. Для артефактов рекомендуемый логический layout: `${SEO_ARTIFACTS_DIR}/<project>/seo/<run-id>/`; для читаемых решений — `${PROJECT_DOCS_DIR}/<project>/`.

- Проверить, что artifact/temp/doc roots не находятся внутри checkout и live skills. Для чувствительных исходников применять ограниченные права доступа и сроки хранения.
- Не хранить рабочие данные или секреты в skills, fixtures, памяти или Git. `.gitignore` — страховка, не защита от уже отслеживаемых файлов и не permission boundary.
- Выход HTML checker создаётся эксклюзивно: существующий файл не перезаписывается. Runner тоже требует новый внешний каталог отчёта.
- Test runner требует `TMPDIR`, не выбирает implicit системный temp; unittest fixtures используют его явно. GitHub Actions передаёт `${{ runner.temp }}`. Локальные tests не создают tempfiles рядом с исходниками.
- Путь структурного валидатора вычисляется от `__file__`, не от cwd и не от установленной копии навыков. В standalone checkout default root — `skills/`, декларация host skills — `docs/host-dependencies.json`. Для установленного дерева передавайте root и declaration явно, если документ не расположен рядом.

Никакие значения переменных здесь не дают разрешения на публикации, расходы, чтение чужих данных, изменение профилей, установку интеграций или расширение OAuth scopes.
