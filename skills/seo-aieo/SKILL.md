# SEO/AIEO: полный рабочий цикл

## When to Use
Для полного SEO/AIEO-аудита, запуска продвижения, стратегии, очередного цикла улучшений либо задачи, затрагивающей несколько SEO-этапов. AIEO/AEO/GEO здесь обозначают работу с видимостью в ответах ИИ, не отдельную гарантированную формулу ранжирования.
Узкую задачу направляй в соответствующий навык; не загружай всю библиотеку каждый раз.

## Procedure

### 1. Восстановить контекст и выбрать режим
1. Прочитать проектный README, предыдущий SEO-отчёт, журнал изменений и manifest. Сверить домен буквально, account/property, рынки, языки, продукт, конверсию, владельца и срок. Не объединять проекты и языки по сходству названий.
2. Выбрать `baseline` (исходная картина), `audit`, `strategy`, `implementation`, `measurement` или `full-cycle`. Для «полностью» использовать full-cycle, но не пропускать подтверждения внешних действий.
3. Создать проектный каталог артефактов и заполнить `templates/project-brief.md`, `templates/project-manifest.json`. Неизвестное оставить null/unknown, не назначать молча платный стек.
4. Объявить границы: доступы, URL/временной/API-бюджет, исключения, рынки, критерии завершения. Для незаданного публичного экспресс-аудита разумный начальный лимит — 30 HTML-страниц, последовательные запросы с паузой ≥1 секунда, без обхода блокировок; это ограниченная выборка, не полный crawl.

### 2. Проверить источники, а не наличие инструкций
Загрузить `references/data-sources.md`. Инструмент найден ≠ авторизация работает ≠ нужный проект доступен ≠ свежие данные полны.
- Выполнить минимальный read-only запрос к необходимому источнику; сохранить время, параметры, дату данных и ошибку без секретов.
- Topvisor обязателен для позиций при effective `rank_source=topvisor`; внешний descriptor `rankSource` сопоставлять по `references/identity-handoff.md`, конфликт не скрывать. `rank-tracker-operations` управляет ценой, запуском и полнотой. GSC — другой тип данных.
- Без рыночного API завершить качественную часть исследования, но не изобретать volume/KD/backlinks. Без AI-ответов выдать readiness-аудит, не «измеренную AI-видимость».
- Не чинить MCP-сервер или клиент при ошибке. Использовать безопасную альтернативу для той же задачи либо зафиксировать блокер.

### 3. Пройти нужные этапы
Подробная карта входов, действий, результатов и критериев — `references/lifecycle.md`.

| Задача | Владелец |
|---|---|
| Бизнес-цели, спрос, SERP, конкуренты, семантика, прогноз-сценарии | `seo-research-strategy` |
| Crawl/index/rendering, CWV, schema, логи, инциденты | `technical-seo-audits` |
| Query→URL, структура, перелинковка, programmatic, миграция | `seo-site-architecture` |
| Бриф, исследование, текст, on-page, проверка фактов, публикационный пакет, обновление | `seo-content-operations` |
| Промпт-панель, реальные ответы, цитаты, достоверность, AI-логи/console exports | `aieo-visibility` |
| Ссылки, упоминания, полезные активы, PR, черновики обращений, размещения | `seo-authority-promotion` |
| Local/GBP, commerce, international, Яндекс/Алиса, image/video/news | `seo-specializations` |
| Результаты, отклонения, эксперименты, очередной цикл | `seo-reporting-monitoring` |
| GSC, SERP-позиции и аналитика конверсий | соответствующие GSC / rank-tracker / GA4 навыки |

Параллельно делегировать только независимые срезы. Передавать точные входы, границы, выходной файл и критерий проверки. Родитель проверяет доказательства, объединяет дубли и принимает результат. Claude slash-команды и имена чужих агентов не являются инструментами этой среды.

### 4. Собрать единую очередь работ
В `templates/backlog.csv` каждая рекомендация имеет evidence ID, URL/шаблон, влияние, уверенность, трудозатраты, зависимость, владельца, критерий проверки и откат. Приоритет — решение на основе этих полей, не псевдоточная сумма «SEO-баллов».
- P0: подтверждённый инцидент с большим действующим ущербом, например случайный sitewide noindex после выпуска.
- P1: подтверждённый блокер важных страниц/измерения.
- P2: проверяемая возможность роста.
- P3: эксперимент или косметика без доказанного ущерба.
Не объявлять отсутствие meta description или llms.txt критическим инцидентом.

### 5. Внедрить только разрешённое и проверить
Локальные черновики/аналитику делать сразу. Перед расходом денег, отправкой сообщений, изменением CMS/GBP/индексации, удалением или публикацией показать точный набор действий/стоимость/дифф и получить подтверждение. Существующие CRM approval-процедуры не обходить.
Использовать `templates/change-plan.md`: backup → scoped diff → тест → подтверждение → применение → чтение именно изменённых URL/записей → сравнение → откат при нарушении условий. Деплой не доказывает индексацию; индексация не доказывает рост.

### 6. Замкнуть цикл
Зафиксировать baseline, применённые изменения и даты; сравнивать одинаковые сегменты/периоды. Сохранить проверенный отчёт, очередной список действий и точную дату повторного измерения. Новое расписание/платный recurring запуск создавать только после согласования параметров и доставки.

## Outputs
Минимальный пакет: brief/manifest, карта покрытия этапов, источники и evidence, данные с методикой, приоритизированная очередь, материалы/диффы, журнал применения и проверки, отчёт с ограничениями. См. `references/data-contracts.md` и `references/acceptance-tests.md`.
Читаемые решения — в `${PROJECT_DOCS_DIR}` (проектные документы/Vault); raw HTML, ответы, выгрузки и тестовые артефакты — `${SEO_ARTIFACTS_DIR}/<project>/seo/<date>/`, не в памяти и не в git без отдельного запроса.

## Pitfalls
- Набор SKILL.md не предоставляет API, краулер, ключи и рост трафика автоматически.
- Не устанавливать коллекции навыков/хуков вслепую. Для расширения читать `references/donor-policy.md`.
- Неизвестное ≠ ноль; ошибка ≠ отсутствие упоминаний; публичный `site:` ≠ размер индекса.
- Нет универсального word count, плотности ключей, AI-schema, llms.txt-бонуса или гарантированного GEO-ROI.
- `dry-run` в чужом CLI не гарантирует отсутствие внешних действий: сначала проследить код.

## Verification
- Все применимые этапы имеют статус и доказательство; `not_applicable` требует причины, `blocked` не превращается в done.
- Данные и выводы различают observed / derived / hypothesis / unknown; сборка итогов выполнена кодом, не в уме.
- Позиции, показы, AI-цитаты, referral sessions и подтверждённые бизнес-результаты не смешаны.
- Каждый выполненный external write прочитан обратно, платные операции имеют согласованный предел.
- Ответ содержит сделанное, проверенное, не выполненное и следующий конкретный шаг; не обещание будущей работы.
