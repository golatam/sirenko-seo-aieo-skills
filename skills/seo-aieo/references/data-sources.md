# Источники данных: выбирать по вопросу

## Перед подключением
Использовать существующий разрешённый инструмент, сначала discovery → точная схема → маленький read-only запрос → проверка нужного account/property → проверка полноты/свежести. Не создавать MCP и не покупать подписки лишь потому, что они есть в каталоге. Для нового подключения использовать уже одобренный в среде helper авторизации; не просить секреты в чате.

| Вопрос | Источник | Что он НЕ доказывает |
|---|---|---|
| По каким запросам находят наш сайт? | GSC Search Analytics, Яндекс.Вебмастер | Полный рыночный спрос, точные live-позиции |
| Индексирует ли поисковик конкретный URL? | URL Inspection / Webmaster index status при реальном доступе | Гарантию будущего ранжирования; HTTP 200 этого также не доказывает |
| Где позиции заданных ключей? | Topvisor или явно выбранный rank provider | Конверсии, AI-цитирования |
| Каков рынок, volume, SERP, ссылки конкурентов? | Один подходящий Ahrefs/Semrush/DataForSEO/SE Ranking либо датированная выгрузка | Реальный трафик/выручку конкурента; прогнозы остаются оценкой |
| Какие HTTP/DOM/ссылочные проблемы? | Ограниченный публичный fetch/browser; глубокий crawl через проверенный crawler/export | Полный сайт без раскрытия охвата; GSC index state; полевые CWV |
| Как видит сайт реальный пользователь? | Browser + CrUX/RUM; Lighthouse отдельно как lab | Любой Lab-score не равен полевому CWV |
| Что ИИ действительно сказал и процитировал? | Реальный capture/export конкретной поверхности, native reports отдельно | Consumer UI из обычного LLM API; причинный рост от GEO-score |
| Каковы агрегаты AI-видимости в поиске? | Google AI report, Bing AI Performance, Яндекс «Видимость сайта в Алисе AI» — методика в `aieo-visibility` | Общий знаменатель, доступность API по факту существования UI, полный рынок или исходные ответы |
| Кто посещал страницы? | GA4/другая разрешённая аналитика и очищенные server/CDN logs | Личность бота по одному User-Agent; деньги по browser revenue |
| Какие заявки/продажи качественные? | Согласованные обезличенные CRM/ledger события | Что каждую продажу вызвало SEO |

## Проверка подключения
Запись в manifest: `source`, `purpose`, `account_or_property`, `status`, `checked_at`, `data_as_of`, `evidence_path`, `cost_policy`, `scope_limits`.
Статусы: `not_checked`, `available`, `partial`, `blocked`, `not_required`. `available` означает реально выполненный нужный тип запроса, не установленный скилл.

## Минимальная конфигурация
Для полезного публичного аудита достаточно HTTP/browser и файлов. Для регулярной работы добавлять существующие GSC + Topvisor + фактическую аналитику проекта. Выбирать один рыночный источник под необходимые покрытия и экономику. AI-провайдер нужен только для автоматического регулярного сбора; ручные или имеющиеся выгрузки с provenance допустимы и не выдаются за автоматическую интеграцию.

До платного действия: точные endpoints/операции, число ключей/промптов, рынки/устройства, число повторов, лимит расходов, ретраи и срок действия согласия. Не считать read-only вызов бесплатным: API чтения тоже может тратить credits. Не повторять charged job после timeout, пока не проверен её статус.

## Изменчивые возможности
URL endpoint, планы, API dimensions и rich-result eligibility проверять в текущей официальной документации и фактической схеме инструмента. UI-отчёт не означает API-поддержку. Не добавлять несуществующий `search_type` для Generative AI, не «угадывать» инструменты поставщика. Список доступных tools отражает только эту сессию.
